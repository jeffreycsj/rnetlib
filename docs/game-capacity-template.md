# 游戏网络容量与 SLO 验收单

复制此模板用于一个冻结候选、一个目标部署。所有空项均为**未验收**，不是默认通过；不得从回环结果推导生产连接数。功能/API、监控/告警完成后，先短时目标验证，再弱网，最后 24–72 小时长稳。本模板不执行任务。

| 项目 | 部署方填写 |
| --- | --- |
| 验收负责人、日期、故障联系人 | 待填 |

| C/C++11/Go/Rust/C# 调用栈及实际版本/架构 | 待填；不得混搭不同 native 与 wrapper |

| 发生器与服务器机器/网络路径、DNS/IPv4/IPv6 | 待填；区分同机进程与实际跨机 |

## 必须先定义的目标

| 目标 | 口径及填写项 | 验收值 |
| --- | --- | --- |
| 业务可用性 | 成功完成业务数/合法业务尝试数，明确重复、重试和排除项；不是 send 返回成功数 | 待填 |
| 负载达成率 | admitted/offered，时间窗、发生器调度漏 tick、背压及最低有效样本数 | 待填 |
| 端到端延迟 | 业务请求→响应 P95/P99/P999，单位、窗口、最少样本、采样误差；不是心跳 RTT | 待填 |
| 心跳与队列 | 窗口/累计明确区分；P99 上限、超时容忍度、各层占比及 burst 后恢复期限 | 待填 |
| 可靠交付 | TCP/KCP 已 admitted 的实际回包数、drain 上限、业务去重/排序；零未解释缺失 | 待填 |
| UDP 质量 | 往返未观察回包、duplicate/reordered/too-old/late，不能写成单方向物理丢包 | 待填 |
| 资源与公平 | RSS 平台/斜率、CPU、fds、socket/KCP 缓存、慢玩家/优先级饥饿、恢复时间 | 待填 |
| 可追溯性 | 日志丢失/异常上限、关键原因覆盖、metric 缺失/重置处理、通知送达期限 | 待填 |
| 升级与回退 | 停新流量→排空→重新登录；触发条件、最大影响玩家数、恢复时限 | 待填 |

多个实例/发生器分别保留样本数及原始数据，不能平均 P99 得到全局 P99。无样本不能通过延迟项；零压测流量不能通过容量项。任意 SDK/应用层预算扩大都要重新核对 RSS 与邻居隔离，不用“多加内存”替代归因。

## 分阶段证据（顺序不能颠倒）

1. **功能冻结**：当前所有 API、安全切换、恢复语义、日志契约和业务联调通过；不支持项明确给接入方。
2. **仓库/包门禁**：干净提交执行发布 suite（含 ops-test 的 make check、Loom、Go race、MSRV、fuzz/ASan、Miri、依赖检查和交付包联调）。归档报告与日志，未跑/资源阻塞不得填通过。
3. **监控演练**：在隔离环境验证采集失败、logger 异常、队列压力、超时、服务发现缺失、counter 重置与通知送达；应用 watchdog 要能识别“HTTP 正常但不 poll”。
4. **目标环境短测**：真实调用语言与业务消费者，独立发生器；记录 offered/admitted/received 和全部限额，先验证测试本身不是瓶颈。
5. **授权弱网矩阵**：逐传输覆盖约定 RTT、抖动、丢失、乱序、重复、黑洞、DNS/地址切换、断线重连和加密策略切换；记录故障注入/清理及权限，禁止未经批准修改线上 tc。
6. **最终长稳**：功能冻结后执行约定 24–72 小时（待填）；周期性 burst、churn、慢消费，验证 RSS 平台、队列回落、无未解释关闭/日志丢失。长稳中代码或参数变化需重划有效区间。
7. **安全/回退验收**：独立审查范围、遗留项责任人和期限；匹配版本池、账号重新登录、凭据及业务数据回退演练。

## 本次结论

- 结论：未验收 / 拒绝 / 有限制通过（选择并解释，默认未验收）。
- 每项证据地址、命令、开始/结束时间、退出码、源码/包/配置哈希：待填。
- 不通过/未跑/资源跳过及处理人：待填；历史版本绿灯不能继承。
- 允许上线的明确范围、限制和复验触发条件：待填。
- 审批人及回退授权：待填。

当前库硬边界：同进程同 runtime 的一次性恢复、持续正容量 poll、当前 SDK 两端匹配；已进入 socket/KCP 缓存的数据不可撤回。进程重启/滚动部署需要业务重新登录，不能填写“跨实例无感恢复已通过”。
