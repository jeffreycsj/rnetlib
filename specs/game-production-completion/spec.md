# 游戏网络库剩余生产能力：分批交付

## 需求概述

继续补齐现有 `rnet-game` 与 C/C++11/Go 游戏门面中尚未实现的能力，但不把“已有短时本机测试”宣称为目标环境生产认证。先交付无需变更 wire 或业务投递语义的跨语言可观测性，再分别设计需要明确安全、部署和性能边界的能力。

## 行为规格

### 第一批：跨语言游戏层可观测性

- 当 C、C++11 或 Go 调用方查询运行时时，系统应提供与 Rust 相同语义的心跳、恢复、时钟同步和游戏日志累计指标；未配置日志时应明确返回“不可用”，不能伪装成零丢弃。
- 当调用方配置游戏结构化日志回调时，系统应只上报低频生命周期/安全/质量事件，不记录业务 payload、票据、身份或密钥；回调不得阻塞网络工作线程，且回调失败/过慢要可计数。
- 当运行时停止或销毁时，系统应保证回调上下文的生命周期安全；不允许回调重入造成死锁或 use-after-free。
- 新 C ABI 只能追加符号/结构，旧结构布局及符号保持不变；C++11 和 Go 使用同一游戏层语义，不能借用传输运行时句柄。
- 指标和 Prometheus 不添加玩家、session、票据等高基数或敏感标签；累计计数与窗口分位数的区别在 API 注释中说明。

### 后续批次及边界

- 版本范围协商需要新的受认证服务端选定版本响应和新 wire 版本；禁止客户端仅凭本地交集自行降级。
- 跨实例恢复暂不实施：用户确认不需要该能力。现有单实例票据保持原语义，文档不得冒称其支持集群或滚动迁移。
- TCP/KCP 传输队列撤回只承诺“尚未交给 socket/KCP 协议栈”的帧，必须维护 FIFO、安全/控制帧顺序和有界内存；已写入的可靠数据不能承诺撤回。
- 目标环境长稳验收需要用户提供部署拓扑、机器/网络资源、负载模型及 SLO；本机 smoke/soak 只作为预检。

## 技术设计

- 复用 Rust 已有 `heartbeat_metrics_snapshot`、`resume_metrics_snapshot`、`clock_sync_metrics_snapshot`、`game_logger_snapshot` 和有界 `BoundedLogger`，避免两套计数来源。
- C ABI 在游戏专属模块追加固定布局快照和日志配置入口；配置只能在创建时完成，避免回调和运行时并发替换。沿用现有 C 日志回调的生命周期约束，并对游戏事件采用稳定的字段语义。
- C++11、Go 门面只做类型安全转换和生命周期管理，不在包装层重新统计。
- 纯逻辑：快照结构映射、可用性标志、溢出安全转换；副作用：有界异步日志投递、FFI 回调和运行时销毁。

目标环境的部署拓扑、机器/网络资源、负载模型、持续时间以及延迟/丢包/内存 SLO 是多少？这些输入不阻碍版本协商或队列工作，但决定最终长稳验收方案。

## 第一批对抗性审查记录

- 修复：游戏 C 日志回调的 `runtime` 字段原为 Rust 内部诊断编号，现映射为可直接用于 C API 查询的公共运行时句柄，并有回归测试。
- 修复：回调耗时查询采用新方法，保留公开的 Rust `GameLoggerSnapshot` 原有字段形状。
- 修复：Go 回调 panic 不跨越 C 边界，单独计数并进入 Go 游戏指标与 `rnet_game_go_logger_panics_total`；该计数与 Rust/C 原生 sink-panic 计数来源不同。
- 验证：`make check`、`go test -race ./go/rnet`、`git diff --check` 均通过；尚未执行目标环境长稳验收。
