# 游戏场景 Profile 与安全默认配置（已确认规格的实现切片）

## 需求概述

补齐游戏网络 v1 已确认但尚未落地的 `GameProfile`：调用方可按实时、不丢包的可靠实时、会话型游戏选择安全默认配置，无需重复理解 TCP/UDP/KCP。保留现有显式 `transport` 字段和接口，profile 只提供追加式构造入口，不进入 wire，连接建立后也不参与每次发送。

## 行为规格

- 当选择 `Realtime` 时，系统默认使用 UDP，服务端业务加密默认开启。
- 当选择 `ReliableRealtime` 时，系统默认使用 KCP，服务端业务加密默认开启。
- 当选择 `Session` 时，系统默认使用 TCP，服务端业务加密默认开启。
- Rust 应为精确版本、范围版本、数字地址和域名配置提供 profile 构造器；客户端仍不暴露加密开关。
- C 提供稳定 profile 常量和默认值查询；未知 profile、空输出指针明确返回 `INVALID_ARGUMENT`。
- C++11/Go 提供类型化 profile 和配置构造辅助；旧字段、结构布局和显式 transport 用法保持不变。
- profile 不宣称改变可靠性、安全 wire、队列或恢复语义；高级调用方仍可使用已有显式 transport 配置。

## 技术设计

- **纯逻辑**：`GameProfile -> Transport` 的固定映射与有效值校验。
- **Rust 配置**：追加关联构造函数，生成已有配置结构，不新增结构字段。
- **跨语言**：C 追加一个默认值查询符号；C++11/Go 在包装层构造已有配置。
- **副作用**：无；监听、连接和发送继续走现有实现。

## 兼容性

现有配置结构不加字段，旧调用方无需修改；profile 只在创建配置时展开成原有 transport 和初始加密值，wire v3/v4 均不变化。

## 对抗性复审

- C ABI 直接复用 Rust `GameProfile` 的有效值校验和 transport 映射，避免两份映射随版本演进而漂移。
- C++11 服务端辅助函数消费 C ABI 返回的 `initial_encryption`，不会在包装层复制安全默认值；客户端仍没有加密开关。
- profile 只生成既有配置，不进入 ABI 结构体或 wire，因此不会改变旧调用方布局和通信兼容性。
- profile 是推荐起点而非容量或安全认证；显式 transport、运行时安全切换、弱网准入和长稳门禁仍遵循原接口与部署要求。
