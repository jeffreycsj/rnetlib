# 从 Rust FFI 自动生成 C 头文件

状态：已实现并完成本机验证。固定 cbindgen 0.29.2，保持当前 C API 和 ABI 版本 4；常量源码表现差异见下文。

## 目标与边界

以 Rust C ABI 声明为唯一结构化来源，使用固定版本 cbindgen 生成 `rnet.h`，停止手写维护函数声明、成员布局和常量。库使用方直接获得头文件和同批静态/动态库，无需安装 Rust 或 cbindgen。

不改网络协议、SDK ABI 版本、运行逻辑或默认安全策略；不删除 C++ RAII、Go 和 C# 包装层，也不在本批自动生成全部语言 SDK。保留当前 C 函数、字段、typedef 名称与回调调用约定，验证 C11/C++11、cgo 和 C# 原生布局。

## 已核实的迁移点

- rnet-ffi 已生成 rlib/staticlib/cdylib，但尚无 cbindgen 依赖或配置；发布脚本直接复制手写 include/rnet.h。
- Rust 结构体大多有 repr(C)，但许多成员和常量的详细注释仅在 C 头中，需要迁回 Rust 声明，不能让自动生成丢失文档。
- C 句柄 typedef 与部分独立回调 typedef 在 Rust 签名中仍为原始整数/内联函数指针；需补齐等价类型别名，并配置对外命名。
- 部分 C 错误常量未在 FFI 中完整声明，其他常量引用内部枚举值。生成须解析出相同数值，不能暴露内部依赖类型或复制一套无法校验的数值。
- 当前导出检查依赖函数声明的单行格式；文档检查主要检查 AST 声明，宏不在范围内。需适配生成格式，不能通过降低检查覆盖率使门禁通过。

## 行为规格

- 构建 rnet-ffi 时自动生成本次源码对应的头文件；生成失败即构建失败，不静默沿用旧头文件。
- 普通 Cargo 构建写入 OUT_DIR，不修改源码树；开发者通过明确的更新命令刷新受版本控制的 include/rnet.h，方便 C/C++/cgo 开发与审阅。
- 检查命令将重新生成结果与 include/rnet.h 比较：声明、数值或文档过期均失败，不自动覆盖后再报告通过。
- 正式构建/打包先执行一致性检查，发布的头文件必须来自已校验结果并与本次库源码对应。发布包消费者不依赖生成器。
- 连续生成内容一致，不包含绝对路径、当前时间或其他机器相关内容；生成器版本固定并受 Cargo.lock 约束。
- 缺依赖或离线缓存不足时明确报错；本机安装/下载只在实施时按权限和内存规则进行。本设计阶段不安装工具。

## 技术设计

1. **FFI 声明与文档**：在现有职责模块补齐类型别名、常量和文档。仅等价替换原始类型，不改变字段顺序、对齐、指针 const 性或空回调表达。若生成器不能处理内部枚举引用，可使用显式 ABI 数值并以编译期断言/测试绑定内部枚举，避免数值漂移。
2. **生成器配置**：固定兼容项目 Rust 工具链的 cbindgen 版本；通过配置控制 C 输出、include guard、extern C、标准头、类型重命名及导出范围。仅允许公共契约说明作为固定头注释，不在模板中手写函数/结构体/常量。
3. **构建与更新入口**：build.rs 将头文件生成到 OUT_DIR，声明正确的输入依赖；提供统一更新/检查命令和 Make 入口。从 Cargo 的结构化构建消息定位输出，避免猜测 target/debug/build 的哈希目录，支持自定义 target-dir。
4. **发布与 CI**：一致性检查接入 make check、ABI 检查和发布前校验。生成文件标注禁止手改；CI 拒绝过期头文件。保持普通 Rust 编译不写仓库，避免只读源码或并发构建互相覆盖。
5. **独立验证**：保留既有导出清单作为人工确认的公共表面；用 C/C++ 编译检查与 Rust 对照验证常量、函数指针类型、sizeof/alignof/offsetof，不能仅以生成器输出校验自身。迁移前基线用于验证本次无破坏变更，不作为另一份日常维护的头文件。

常量的生成形式（如匿名 enum 成员变为宏）可能不同，但必须保持公开名称、数值、常量表达式用途和目标语言可用性；预处理器使用方式、cgo 类型与文档覆盖需要单独检查。若出现影响既有公开用法、且不能等价适配的变化，暂停该项并说明，不擅自升 ABI 或加入旧版本兼容层。

## 完成标准

开发者仅修改 Rust FFI 定义与注释即可更新 C 头；生成检查能识别未更新文件；当前接入代码不需修改即可通过；发布包携带可直接使用的匹配头文件和库。未通过或未执行的目标平台测试如实记录，不据此宣布生产资格完成。

本批不启动目标环境长稳，不提交或推送；构建/测试串行并始终保留至少 15 GiB 可用内存。

参考：[cbindgen 官方使用说明](https://github.com/mozilla/cbindgen/blob/main/docs.md)。其支持从公共 C API 生成头文件、build.rs 集成和输出配置，但具体常量/类型支持须以本仓库生成与编译回归验证。

- 24 个结构体的 303 个字段及 55 个导出函数注释迁回 Rust，补齐 76 个常量和 C 名称别名；保留既有 Rust 裸回调别名。超出模块长度的游戏指标定义/转换独立到 game_metrics_abi，不扩大结构门禁。
- 迁移前基线通过 native-doc-check/abi-check。独立 Clang AST 类型规范化与实际 C 程序验证：108 个命名声明、76 个常量、24 个结构体的大小/对齐及 303 个偏移与旧头相同。证据位于 `/tmp/netlib-header.D08biE`，不是由新生成器自行证明其输出；尚不代表其他平台验证。
- 第一组 RED：旧 Cargo 构建没有 OUT_DIR 头文件；实现后通过。脚本测试覆盖包 ID 选择、缺失/歧义/失败构建、陈旧文件不覆盖、原子更新和不变输出的 mtime。常量转宏后另建 RED 并补宏文档门禁，487 项 C 声明/宏均有文档。
- 构建工具仅引入精确版本 cbindgen，MPL-2.0 许可例外限于该 build dependency；不链接到运行库。新增依赖选择时使用 MSRV 回退，当前锁定的直接生成器 Rust 下限为 1.74，indexmap/hashbrown 下限不超过项目 1.85；这不是实际运行 Rust 1.85 编译的替代证据。

### 对抗性/API 契约复查

本地 C ABI 面向 Rust/C/C++/Go/C# SDK，不套用 REST 资源、分页或 HTTP 错误格式规则。重点核对名称、单位、可空性、错误类别、布局、当前版本边界与文档。大型 diff 主要来自文档迁移和生成排版，未混入网络行为改动；后续提交应区分生成基础设施与机械迁移，当前不执行提交。

| 级别 | 发现与处理 |
| --- | --- |
| 必须修复 | cbindgen 将 Option<回调别名> 生成为不完整结构体，候选 C 头实际编译失败。改为等价内联可空函数指针，保留原 Rust 裸函数别名，以编译期类型赋值检查关联。只对该字段注明原因并允许 type_complexity，不关闭其他 Clippy 检查 |
| 必须修复 | 原注释门禁不覆盖宏；转宏会漏检常量文档。补真实 Clang 配合源码宏检查及 RED/GREEN，排除空 include guard，不把注释示例当声明 |
| 必须修复 | 脚本捕获 Cargo metadata stderr / JSON compiler-message 后丢失具体原因。分别以外部 Cargo 进程边界回归复现，再保留 stderr/rendered 诊断，失败仍不更新头文件 |
| 契约差异 | 常量成为宏，数值和常量表达式用法相同，但现在可被 #ifdef 检测，C++ decltype/模板推导也由匿名枚举变为整数类型；开发说明明确，不拿二进制布局一致推断所有源码表达式兼容 |
| 注释保护 | 补回原 C 独立说明中的事件诊断可缺省、SECURITY_CHANGED 二进制格式与 game logger 不输出凭证的契约，不只迁移 AST 可见的注释 |

测试盲区与资格边界：尚未覆盖所有平台、真实磁盘满/进程中断；独立 C 对照仅本机 Linux x86_64。生成器异常、外部 Cargo 失败与发布前检查不等于生产网络长稳或第三方安全审计。本批未执行目标环境长稳、ASan fuzz、Miri 或 Rust 1.85 实机编译，不延用历史资格结论。
