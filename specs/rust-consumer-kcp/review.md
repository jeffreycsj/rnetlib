# KCP 外部 Rust 接入：对抗性审查与验证

日期：2026-10-28。范围：隔离 KCP 修正版、两张构建依赖图、独立消费者测试、
CI/Make 门禁及打包来源记录。保持 SDK API/ABI/wire 不变。

## 发现的问题及处理

| 严重度 | 问题 | 处理与验证 |
|---|---|---|
| 高 | 本地 crate 改名后，普通审计不能再识别原始 kcp 版本的公告 | 保留原始 registry 名称、版本和源包 hash 的身份锁；真实依赖门禁额外执行上游身份审计，失败即阻断 |
| 中 | 新 Make 目标一度抢占默认构建入口 | 已调整目标位置；已有默认目标保护测试捕获并验证修复，裸 make 仍构建库 |
| 中 | 只检查 all-features 会漏掉条件编译另一分支 | 默认 workspace 严格 Clippy/测试与 all-features KCP 测试分别执行；可选特性另外通过 Clippy 和 Rust 1.85 检查 |

算术逐类核对：时钟/序号使用半空间模运算；ACK 查找不能使用普通整数排序；
RTT 中间值扩大位宽；重传次数饱和、退避有上限；长度/MTU 校验不得回绕。
上游文件逐一与 SHA-256 校验过的源包比对，MIT 许可随 SDK 打包。

## 测试质量与结果

- 原有适配层 5 项测试先通过；外部 workspace 的真实分片流量在旧依赖上触发溢出。
- 本地引入的 6 项边界测试先全部失败，修复后通过；最终含可选异步路径共 10 项。
- 测试注入内部序号而不是伪造运行时公开接口，真实走分片、乱序、一次丢包、
  接收重组、ACK 和重传；验证发送队列排空、负载相等且没有重复交付。
- 独立 Rust workspace 使用默认 test 和受检 release，无 profile/patch 修复，
  两种构建各通过新增流量测试和既有 5 项适配层测试。
- 50 项脚本测试通过；消费者失败不会被下一种构建掩盖，上游身份扫描失败会阻断门禁。
- 完整九项门禁均通过：check、go-race、msrv、fuzz-build、fuzz-asan、miri、
  supply-chain、package、package-smoke。check 含 Loom、ABI、C/C++11/Go/C#。

证据目录：`target/release-evidence/rust-consumer-kcp-20261028/`。
所有门禁的源指纹一致：
`0f491ffd52f9a1d9abc1b9ec459534ae58be72b10021b22c1858ee9fb10da7a5`。
该目录被 Git 忽略，不代替永久 CI 归档。本审查记录和最终规格状态在验证后补写，
不属于上述指纹；详细包 hash 见仓库生产资格记录及门禁 JSON。

## 测试盲区与整体评价

本轮已修复外部 Rust 消费者依赖根 profile 的缺陷，但没有完成生产认证。
九项命令通过不等于汇总通过：汇总为 `incomplete`，原因是工作区未提交，
不是测试失败或门禁期间代码变化。尚需干净发布提交的重新验证及持久归档。
六目标 ASan 每项仅十秒；Miri 仅覆盖 core/protocol，未覆盖完整 KCP/Noise。
未执行目标机器长稳/弱网矩阵、独立第三方审计、远端 CI 或其他平台资格验证。
按既定安排，目标环境长稳放在库功能和发布候选收敛后，不在本轮启动。
