# 游戏 wire v4 版本协商与可靠传输待发快照淘汰（已确认）

## 需求概述

保留现有 wire v3 精确版本 API 和行为，为需要多个业务协议版本的游戏新增受服务端认证的版本协商；同时让 `LatestOnly` 在 TCP/KCP 已进入传输待发队列、但尚未写入 socket 或交给 KCP 协议栈时仍能按 `(session, key)` 尽力替换旧快照。跨实例恢复不在本期范围内。

## 行为规格

### 版本协商

- 当调用方继续使用现有 `GameProtocol`、`listen`、`connect`、`connect_resume` 时，应保持 wire v3 精确匹配，不修改已有公开结构体、C 布局和符号语义。
- 当调用方明确选用新范围配置时，应使用独立的 wire v4 加入标记，客户端发送非零 `protocol_id`、闭区间 `[min_version, max_version]`、构建/能力元数据及一次性协商 nonce；旧 v3/v4 不能静默混用。
- 当两端版本范围有交集时，服务端应选择交集中的最高版本；无交集应在业务授权前拒绝。选定版本须在 Noise 保护的服务端控制消息中与该 nonce、协议 ID 和本次会话绑定；客户端必须验证选定值在自己的范围内。
- 当服务端完成业务授权后，应重发有界的选定版本控制消息直到客户端确认或超时。服务端收到确认后才发布就绪；客户端收到服务端最终确认后才发布就绪。UDP 丢失/重复/乱序控制消息不得产生两个就绪事件；在客户端等待最终确认时到达的受保护业务消息须有界暂存，超预算明确关闭而非静默丢弃。
- 当应用处理范围会话的授权请求时，应能查询该会话的选定协议版本；Rust、C、C++11、Go 均有入口。无版本协商完成、句柄失效或越权角色调用要有确定错误。
- 当客户端持有单实例恢复票据时，恢复会话必须固定票据原选定版本；请求范围不包含它则拒绝，不借恢复升级/降级。仍须新句柄、重新业务授权和 v4 就绪确认。

### TCP/KCP `LatestOnly` 传输待发淘汰

- 当同一会话同一 key 的新快照到达、旧快照尚在传输待发队列时，应原位替换并立即释放旧快照的字节预算；不同 key 保持公平顺序，普通可靠 FIFO 和安全/控制消息顺序不变。
- 当旧快照已开始 socket 写入或已交给 KCP 协议栈时，不能宣称撤回；新快照按正常有界背压规则入队。UDP 保持现有语义。
- 当会话关闭、换代或发送失败时，应清理对应 key 和预算；高并发替换不能造成重复发送、内存超限或负计数。
- 暴露“游戏层替换”“传输待发替换”“已写出不可撤回”和发送失败的分原因累计计数，Prometheus 无玩家/session 标签；跨语言通过追加式 ABI 查询，不更改现有 `rnet_game_metrics_t` 布局。

## 技术设计

- **公开 API**：新增独立 `GameProtocolRange` 与范围配置/调用入口，普通 API 不增加必填参数；C ABI 仅追加符号及新结构，C++11/Go 与 Rust 对齐。范围模式仅在显式调用时启用。
- **wire/state**：v4 加入编码、严格解码、受保护选定/确认/最终确认控制状态机。限定每会话状态大小、重试次数和期限；握手消息不得进入业务 `Message`。选定版本与恢复票据状态绑定。
- **待发队列**：不尝试从 Tokio `mpsc` 中按键删除；为可替换数据引入有界的 per-key 待发槽，I/O worker 取得槽内容时转为不可撤回。普通消息和控制帧仍走现有顺序约束，预算随槽替换/取出转移。
- **纯逻辑**：版本交集与状态转换、槽替换预算；**副作用**：Noise 控制收发、socket/KCP 写入、日志/指标。

## API 兼容性审查

- 遵循“追加而非改义”：v3 标记、精确 `GameProtocol`、既有 C 结构体字段/大小、普通 `send` 均不改变。v4 只由新入口启用，拒绝隐式降级。
- `selected_version` 是服务端决定的只读结果，不作为客户端可任意设置的业务消息字段。版本无交集、消息格式错误与协商超时分别返回可追踪错误，且在业务就绪前发生。
- 此处借用 AIP 的向后兼容、字段语义及错误可诊断原则；资源命名、REST 标准方法与分页规则不适用于本二进制游戏会话 API。

## 已确认的取舍

用户确认采用“服务端选交集最高版本”；范围协商仅走新 wire v4，旧 v3 精确接口不变；`LatestOnly` 只保证尽力替换尚未被工作线程取出的待发槽，不保证撤回已交给 KCP 或 socket 的可靠数据。跨实例恢复本期不实施。

## 对抗性审查记录

- 修复：新 ABI 符号清单排序错误会阻断导出检查；现与头文件顺序一致并通过检查。
- 修复：TCP 工作线程在取出待发快照后重新确认会话仍有效，避免关闭后继续写队列中的数据。
- 验证：同键八线程并发替换只占一个传输槽，替换后预算正确回收；wire v4 的 TCP/UDP/KCP 加入、版本拒绝和单实例恢复有集成测试。
- 结构：`range_api`、`range_state`、`range_runtime` 和外置 runtime/range 测试各自按职责组织，结构检查覆盖所有游戏层源文件。
- 补齐：worker pickup 累计数精确标记可撤回边界，latest 入队失败按稳定错误原因累计；pickup 后发生的 socket/KCP I/O 失败沿用会话关闭原因指标，pickup 本身不表示送达。
- 边界：KCP 协议栈和 socket 已取得的数据不可撤回；本机测试及短时 smoke 无法替代目标环境的吞吐、丢包和长稳 SLO 验收。
