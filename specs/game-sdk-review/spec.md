# 七项生产游戏网络库审查与补齐

沿用已确认的 wire v3/v4、服务端权威安全切换、单实例恢复语义，落实用户本轮七项要求。

## 行为与边界

- C# 使用 C 游戏 ABI，提供 Listen/Connect/Send/Poll、认证、关闭、动态加密、参数配置和指标；不重新实现协议。面向 .NET 8+，首先验收 Linux x86_64；Windows/Unity/AOT 需单独验证。
- 收包复制为托管数组，finally 释放两枚 native token；回调保持存活直到 destroy 完成，异常不越过 native 边界。Dispose 与使用协调，回调禁止 Stop/Dispose、允许只读指标查询。
- 游戏日志默认每 30 秒输出累计延迟分位数，可设置间隔或用 0 禁用，由 poll 驱动，含样本数、P90/P95/P99/P99.9/max、队列及 logger 丢弃。
- 异步错误日志保留具体库内校验原因、句柄和 correlation，不输出凭据或 payload；只有错误码时不得伪装为具体 OS 错误。
- 长稳与目标弱网矩阵仍为最后验收，短时回环不代表容量或安全认证。

## 数据报端点致命退出的统一收尾（已确认）

### 目标与行为

沿用上一轮确认的端点故障通知与句柄回收范围，补齐 UDP/KCP 共享接收任务已经决定退出、却遗留注册表状态的问题。不引入自动重连，不修改 wire、C ABI 或调用方发送接口，不提前执行长稳。

- 当数据报接收任务因本地 I/O 错误终止时，故障端点及其所属会话应失效，释放端点额度、待认证额度、发送队列和相关状态；其他端点不受影响。
- 使用既有 `EndpointError` 和会话失败/关闭事件保留错误码、阶段及有界本地原因。待连接客户端遵循既有加入失败语义。通知发布失败不得阻止资源释放。
- 故障与主动关闭竞争时，由注册表中的移除操作确定清理赢家；不重复发布故障事件、不重复关闭计数、不重复释放额度。主动关闭成功后不补发伪故障。
- 正常启动必须先完成任务中止句柄注册，再允许后台执行，避免立即失败发生在端点初始化完成之前。
- 游戏层清理失效端点的协议、心跳、快照发送和恢复状态；仅凭 `EndpointError` 类型不能判断端点死亡，因为既有 TCP 等路径也使用它报告可继续工作的错误。以底层端点是否已失效区分，并覆盖通知受队列压力影响时的清理。
- 沿用目前导致任务退出的接收错误条件；不在本轮扩展为新的跨平台 ICMP/可恢复错误分类策略。上轮未认证 cookie challenge 发送失败的局部隔离保持不变。

### 技术边界

端点致命故障收尾独立成职责明确的内部模块，复用现有单次会话关闭和诊断预算机制；运行任务负责提供本地错误。游戏层复用主动关闭后的状态清理，但不能递归调用已经失效的底层关闭接口。故障注入仅用于测试 I/O 边界，不在生产 ABI 暴露测试开关。
