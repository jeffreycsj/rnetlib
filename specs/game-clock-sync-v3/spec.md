# 游戏时钟同步 wire v3

## 需求概述

在游戏会话就绪后，用 Noise 保护的内部控制报文进行四时间戳交换，向客户端提供服务端单调时钟与客户端单调时钟的相对偏移估计。wire v3 与现有 v2 加入格式显式不兼容，不静默混用。

## 行为规格

- 普通加入使用 `RGV3`，恢复加入使用 `RGR3`；旧 `RGJ2`/`RGJ3` 均在业务授权前拒绝。应用 `GameProtocol.version` 仍是独立的业务协议版本。
- 客户端就绪后按心跳间隔自动发送有界请求 `(op=1, nonce, t1)`；服务端只在已就绪会话上以 `(op=2, nonce, t1, t2, t3)` 回答。所有时间戳为各自运行时创建以来的单调微秒数。
- 客户端收到匹配、未超时的回复时记录 `t4`，估计 `server_minus_client_us=((t2-t1)+(t3-t4))/2`、`rtt_us=(t4-t1)-(t3-t2)`。只有合法样本进入快照与计数器；客户端可查询自身运行时单调微秒数用于换算。偏移不是 UTC，也不能作为身份、计费或反作弊可信时间。
- 每会话最多一个待匹配请求；错误长度、错误角色或无效操作按协议错误处理；过期、重放、不匹配的回复只计数拒绝，不更新样本。服务端对请求限速，发送背压不能制造假样本或无界积压。
- 关闭/恢复时清除旧句柄的采样状态；新句柄重新采样。应用业务发送接口不增加参数。

## 技术设计

- `join.rs`：更换加入 magic 并补拒绝旧版本测试。
- `clock_sync.rs`：固定长度编码、严格解码、单调算术与每会话状态机；使用 `i128` 中间值避免外部时间戳溢出。
- `clock_sync_runtime.rs`：客户端自动调度、服务端限速回复、快照与累计指标；只调用 `send_game_control`，不经过明文业务通道。
- `runtime.rs`：在 ready/close/poll 控制路径挂接，不污染业务事件。
- C/C++11/Go：追加 `clock_micros` 与 `clock_sync_snapshot` 接口；旧符号和结构布局不变。
