# 游戏网络库生产冻结规格

## 需求概述

在目标环境长时间压测之前完成游戏网络库的功能与接口冻结：修复零容量轮询的存活检测缺陷，补齐可选的优先级、过期时间、关联 ID 和 tick 跨语言发送能力，实现有界公平调度与完整遥测，并解决 KCP 超长会话序号边界。跨实例恢复不在本期范围内。

## 行为规格

### 正常流程

- 当调用方执行 `poll(0, ...)` 时，系统应返回空事件，但仍有界消费内部控制消息并推进心跳、时钟同步和版本协商；待上抛业务事件不得丢失或无界搬运。
- 当调用方使用普通 `send(session, payload)` 时，系统应继续使用可靠普通优先级、无过期和无关联 ID 的默认值，不增加必填参数。
- 当调用方使用高级发送时，系统应允许设置网络调度优先级、本地排队过期时间、可选 tick/sequence 和 correlation ID；业务消息类型仍只在 payload 内。
- 当多个优先级持续有流量时，系统应优先低延迟消息，同时保证低优先级获得有界进展；已过期且尚未交给不可撤回边界的消息应丢弃并计数。
- 当消息携带 correlation ID 时，接收事件和结构化诊断应保留该值；Prometheus 不增加玩家、session 或 correlation 高基数标签。
- KCP 新连接必须在 cookie preflight 中协商随机 conversation，拒绝同地址旧连接报文；完整 32 位序号空间必须使用明确的环绕语义。

### 边界和异常

- 优先级、过期和 correlation ID 均为可选高级参数，不能污染普通发送 API。
- `LatestOnly` 只能替换尚未被 socket/KCP 协议栈取得的数据；不可撤回边界保持不变。
- 过期只表示本地排队期限，不承诺撤回已经写入 socket 或 KCP 缓存的数据。
- 跨实例/滚动重启恢复、Windows/macOS 产物以及业务层玩家身份管理不在本期范围。
- 24–72 小时目标环境长稳压测必须在功能、wire、ABI、指标和文档冻结后执行。

## 技术设计

### 模块划分

- **轮询调度**：零输出容量下使用固定内部事件预算消费控制消息，公共事件继续进入已有有界完成队列。
- **消息调度**：在传输入队前增加有界多优先级调度队列；使用加权轮转避免低优先级饥饿，并在取出时检查单调时钟期限。
- **消息元数据**：基础接口保持不变；高级结构追加 priority、expiry、correlation ID，并由 game envelope/底层安全 frame 传递。
- **可观测性**：追加分优先级入队、过期、背压、排队延迟和 correlation 日志字段；玩家级诊断使用按 session 查询而非 Prometheus 标签。
- **KCP 长会话**：conversation 隔离连接代次；序号是独立的 32 位串号。针对 pinned 依赖仅关闭其包级溢出检查，使 Rust 行为与 KCP 的模 2^32 C 语义一致，不全局降低 RNet 的算术检查。

### 纯度边界

- **纯逻辑**：优先级选择、加权轮转、期限判定、KCP 轮转状态迁移、指标分类。
- **副作用**：socket/KCP I/O、单调时钟、事件队列、日志回调和 FFI buffer。
