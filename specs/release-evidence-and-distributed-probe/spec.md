# 发布证据归档与跨机器游戏探针

状态：三个阶段均已实现并完成本地全量回归及归档包验证。本批不执行长稳或宣称生产认证；剩余目标部署及外部验收边界见各阶段记录。

## 需求与范围

在已具备 TCP/UDP/KCP、统一游戏 API 和多语言接入的基础上，补齐可追溯的发布验收工具与跨机器测试能力。先支持现有验证范围 Linux x86_64 / .NET 8，不改 SDK ABI、网络 wire、恢复范围或生产安全默认值。

现有 `game_soak` 是同一 runtime 的回环探针；接收器通过本进程发送计数校验序号。现有打包脚本有 SHA256SUMS，但没有关联提交、门禁与包哈希的统一证据清单，CI 没有持久归档这些产物。保留已有回环测试，不把它改名后当成跨机器证明。

## 行为规格

### 阶段一：发布证据

- 当执行验收任务时，记录源码提交、工作树状态、工具链、平台、锁文件哈希、命令、开始/结束时间、退出状态及日志哈希；不采集完整环境变量或凭据。
- 当命令失败、依赖缺失、内存不足或任务中断时，保留已有日志并分别标记失败、阻塞或未完成，不标记为通过。资源不足跳过的测试不可充当对应验收证据。
- 当从脏树执行开发验证时，允许产出明确标记的开发报告；正式发布候选要求干净提交，并在结束时重新核对受跟踪输入未变化。报告写到构建输出目录，不制造源码变更。
- 当打包时，为包写入构建来源与工具链信息，再生成覆盖这些文件的校验清单；包外验收报告引用包清单哈希，避免报告与包相互包含造成哈希循环。
- 当 CI 任一门禁失败时，仍归档已生成的非敏感日志及状态；汇总时按同一提交和工作流运行关联各 job，不接受历史绿灯拼接为当前资格。
- 当只有 make check 通过时，报告只声明该集合通过；完整仓库验收另含 MSRV、Go race、供应链、ASan fuzz 与 Miri，不自动宣布目标容量、平台或独立安全审计通过。
- 默认串行执行高内存任务；启动前和执行期间检查至少 15 GiB MemAvailable。无法满足时形成资源阻塞证据，不降低阈值。CI 需匹配资源，不能将受限 runner 的跳过算作验收。

### 阶段二：独立 server/client 探针

- 当启动 server 时，仅创建服务器 runtime，支持显式监听地址、TCP/UDP/KCP、连接与队列预算；当启动 client 时，仅创建客户端 runtime，连接指定地址/主机名并固定校验服务端公钥。
- 当多个客户端进程连接时，按运行标识、负载发生器标识和连接序号隔离统计，不把不同进程的序号混为同一个流。服务端统计不得读取客户端进程内存。
- 当接入测试服务端时，通过 Noise 内的 join ticket 校验测试凭据；凭据从受限文件读取，不放在命令行或报告里。缺少身份校验配置时拒绝启动，不默认开放匿名 echo 服务。
- 测试消息使用探针自身的业务载荷封装，明确运行标识、流标识、序号及校验语义；仅在探针模块中定义，不新增库级 msg_type 或修改 wire。保留已有回环负载格式与测试。
- 当发送被背压拒绝时，不计入已接受发送量；服务端回包重试队列也必须有界。明确统计 offered、admitted、echoed、received、rejected 与最终未完成数量，避免降速后伪装达到目标负载。
- 当 TCP/KCP 运行结束时，在有界 drain 期限内核对可靠收发；未完成则失败。UDP 单独记录未观察到的回包、重复、乱序和窗口外报文；不将往返缺失率描述为单方向物理丢包率。
- 当报告 RTT 时使用同一客户端单调时钟，不拿不同机器的单调时间相减；无采样与零延迟分开。任何未显式配置的 SLO 标记为未评估，不能仅凭进程退出成功认定性能达标。
- 当进程超时、断线、收到坏负载或资源保护触发时，输出明确原因、部分计数及失败结果；测试进程有清理期限，不无限等待。不自动创建远端机器或修改 tc/netem。
- 每个进程报告 CPU/RSS、队列、背压、关闭原因及延迟样本，并记录探针/包哈希、有效配置和运行标识。分进程报告保留，禁止直接平均各进程 P99 得到全局 P99。
- 默认进行短时、少连接的真实子进程验证。跨机器工具完成不等于实际目标环境长稳完成；24–72 小时运行仍留到功能冻结之后。

### 阶段三：运维示例

- 基于现有实际指标补采集、告警和排障示例，覆盖队列持续高水位、丢弃、日志丢失、心跳超时、准入拒绝、关闭原因和有样本的尾延迟。
- 区分累计与窗口统计、计数器重置及无样本，不引入玩家/session 高基数标签，不新建默认对公网开放的管理 HTTP 服务。
- 提供容量/SLO 填写模板及升级回退流程。阈值标为示例，目标机器连接数和性能预算由部署方确定，不虚构通用容量保证。

## 技术设计

- **证据工具**：Python 标准库实现命令执行、流式日志、内存保护、原子状态文件、哈希与汇总；将命令/路径校验和报告判定与子进程 I/O 分离。复用 Make 的测试命令，避免复制另一套门禁定义。
- **构建/CI**：扩展 scripts/package.sh 的来源记录及现有 CI 的日志归档、汇总；保留普通开发打包入口，明确候选包与合格发布的区别。不自动发布、提交或推送。
- **探针**：新增独立二进制，按配置、认证、载荷、server、client、计数报告职责拆模块。仅复用已独立的纯逻辑；不将全部实现堆入现有 game_soak.rs。
- **测试**：证据状态机以临时 Git 仓库和真实子进程覆盖；探针以独立进程使用真实网络库和 socket 覆盖三传输，故障注入限定测试边界。保留现有回环基线。

## 阶段二实施与对抗性复查

- 新增 `game_probe`：配置、文件凭据、业务载荷、server/client、有限重试队列、累计报告分别拆模块。现有 SDK API、wire 和回环探针均不变。
- Noise 公钥固定校验，加密 join ticket 的 HMAC 绑定 run/generator/stream；服务端对运行期间的全部身份去重并限额，不提供匿名 echo。
- 独立真实进程测试覆盖 TCP/UDP/KCP、多个发生器和主机名接入；真实 runtime 故障端覆盖坏回包、可靠回包黑洞、UDP finish ACK 超时；另测背压、重复身份、凭据权限/长度/符号链接与错误公钥。
- 基线原 game_soak 的 3 项单元和 2 项集成测试通过。新 CLI 的缺失二进制、keygen 不适用参数、帮助接口先 RED 再实现；资源跳过误算通过也由真实证据子进程测试复现后修复。

| 复查发现 | 修复/边界 |
| --- | --- |
| 批量 echo 中途失败会丢失已成功入队计数 | flush 返回部分结果及独立错误；回归核对剩余队列预算与已发送数量 |
| 异常返回前 pending 快照可能滞后 | 在入队、出队及时间戳变化时同步计数；黑洞测试检查失败快照仍含未完成量 |
| 负载发生器赶不上调度会伪装较低目标速率 | 错过 tick 仍记 offered/rejected/schedule_missed；不计入 admitted |
| UDP 缺失回包不能等同物理丢包 | 有界序号窗口独立统计重复、乱序、窗口外与晚到；SLO 使用 echo-unobserved 语义 |
| 打包后只测源码二进制不足以验证交付 | 测试支持显式归档二进制路径，package-smoke 使用实际解压包 |
| 短测、无样本和未设置 SLO 容易被误解 | 文档及报告明确 not_evaluated、无样本失败、不做全局 P99 平均和容量承诺 |

## 阶段三实施与对抗性复查

- 运维说明覆盖现有 Rust/C/C++11/Go/C# 采集接口、C buffer 所有权、poll 与日志进度关系、累计/窗口延迟、日志字段与升级回退。容量/SLO 模板默认未验收，要求业务消费者和目标环境填写真实预算。
- 采集配置及 13 条低基数告警以 JSON/YAML 格式随包交付。无新管理 HTTP 服务，不创建外部监控或告警接收人；必须接入宿主已有管理端点及 watchdog。
- 现有 5 项 game_diagnostics 基线通过；真实 runtime selector 契约、配置依赖检查和官方 PromQL 场景先 RED，补齐示例后转绿。全部 13 条告警都有正向求值用例，8 组场景还覆盖重置、零/停更样本、持续时间与恢复、reason/kind、实例与 runtime 隔离。
- `make check` 增加 `ops-test`，发布包验证检查实际归档的规则。验证器缺失立即失败；证据记录实际 promtool 版本。CI 只安装校验 SHA256 的官方离线 promtool 2.55.1，不运行 Prometheus 服务；部署侧仍需按实际版本复验。

| 对抗性复查风险 | 处理 |
| --- | --- |
| 累计 P99 被当作五分钟 P99 或平均成全局 P99 | 规则命名 HistoricalTail，样本变化只作活跃性门槛，文档要求窗口 SLO 另采集 |
| `ignoring` 丢掉 instance/runtime/kind 导致借用其他流的样本 | 仅忽略 quantile，真实 PromQL 测试验证多维隔离 |
| counter 重置被误认为异常增量，或无样本当作低延迟 | 分别测试纯重置无报警、重置后新故障报警、零/停更样本不报警 |
| HTTP 200 空内容被视为采集健康 | game facade 缺失告警；文档要求宿主失败返回非成功状态且不无限缓存 |
| HTTP 健康但游戏线程不 poll | 明确现有指标不能证明事件循环活性，必须接宿主 watchdog，不能宣称示例已覆盖 |
| 将告警常量当成 SDK 自动读取预算 | 文档标出各常量对应的示例容量，部署修改预算必须同步改规则 |
| 外语回调异常不进入 native panic 计数 | 单独说明 Go/C# 现有异常系列与接入查询，不混入 Rust 通用指标契约 |
| 新 Make 目标排在 build 前会改变裸 make 默认行为 | 对抗性复查后主动中断初轮验证；RED 复现并调整目标顺序，增加 dry-run 保护测试 |
